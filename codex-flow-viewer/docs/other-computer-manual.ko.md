# 다른 컴퓨터에서 사용하기 — Windows 매뉴얼

작성일: 2026-10-26. 현재 프로그램 코드·실행 스크립트와 현재 PC의 실제 연결 결과를 기준으로 작성했다. 다른 PC에서의 설치 시험은 아직 수행하지 않았다.

## 1. 무엇을 옮기고 연결하는가

| 사용 목적 | 필요한 것 |
|---|---|
| 프로그램 화면 실행 | 프로그램 폴더, Node.js 24.18 이상, 브라우저 |
| 새 PC의 Codex 기록 보기 | 새 PC의 실제 프로젝트 폴더와 Codex 로컬 기록 |
| 데스크톱 채팅에서 기록 보내기 | 로컬 MCP를 지원하는 데스크톱 앱, flow-viewer MCP 등록, 뷰어 프로젝트 선택 |
| 기존 MCP 대화·메모·고정 이어보기 | 기존 앱의 `.local/viewer.sqlite`가 포함된 데이터 백업 |
| 예전 Codex 기록까지 보기 | 별도로 옮긴 Codex 원본 기록과 기록에 저장된 실제 프로젝트 경로 조건 |

뷰어는 독립 채팅 프로그램이 아니다. Codex 로컬 기록 또는 MCP로 전달받은 질문·답변을 표시한다. API 키를 뷰어에 입력하는 과정은 없다. 데스크톱 채팅 앱의 로그인·사용 권한은 별도다.

같은 계정 로그인만으로 뷰어 DB·메모·고정이 이동하지 않는다. 두 컴퓨터 사이의 자동 기록 동기화나 DB 병합 기능은 없다. `127.0.0.1`은 접속하는 컴퓨터 자신이다.

## 2. 프로그램 폴더 준비

기존 PC에서 아래 폴더를 복사한다.

```text
C:\Users\사용자\Documents\codex-flow-viewer
```

새 PC의 예시 위치는 다음과 같다. 이후 명령은 이 위치를 사용하므로 다른 위치에 놓았다면 경로를 바꾼다.

```text
C:\Tools\codex-flow-viewer
```

`package.json`, `package-lock.json`, `src`, `server`, `scripts`, `public`, `index.html`, 각종 설정 파일과 `start-viewer.cmd` 등 프로그램 파일을 함께 가져온다. 간단하게는 앱 폴더 전체를 복사하면 된다. 큰 `node_modules`와 빌드 결과 `dist`는 제외하고 새 PC에서 다시 만들 수 있다. 개발 문서까지 인계하려면 상위 폴더의 AGENTS.md·docs·design도 별도로 함께 보관한다.

새로 시작할 때는 `.local`을 가져오지 않는다. 기존 기록을 이어볼 때만 아래 백업 절차로 옮긴다. `.local`은 Git 제외이므로 Git으로 소스만 받으면 기존 기록이 포함되지 않는다.

## 3. 기존 기록도 옮기는 경우

1. 기존 PC에서 뷰어 서버를 종료한다. 일반 실행 창은 Ctrl+C로 종료한다. 별도 백그라운드 실행 중이면 해당 뷰어 프로세스를 종료해야 한다.
2. 데스크톱 설정에서 flow-viewer MCP를 끄거나 데스크톱 앱을 완전히 종료해 DB에 쓰는 MCP 프로세스도 멈춘다. 다른 로컬 클라이언트가 연결돼 있다면 해당 연결도 종료한다.
3. 기존 앱의 `.local` 폴더를 원본과 별도의 백업 위치로 복사한 다음 새 PC 앱의 `.local` 위치에 옮긴다. 새 PC에서 이미 쌓은 기록이 있다면 먼저 별도로 백업하고, 덮어쓰기나 자동 병합을 하지 않는다.
4. 새 PC에서 앱과 MCP를 다시 실행한다. 기존 Codex 프로젝트·기록 경로는 옛 PC 경로일 수 있으므로 설정에서 새 PC의 경로를 확인한다.

핵심 DB는 `.local/viewer.sqlite`다. 실행 중인 DB 파일만 따로 복사하지 않는다. SQLite 보조 파일이 남아 있다면 일관된 백업을 위해 `.local`과 함께 보존한다. `.local`에는 개인 대화·이전 사본·검증 자료가 있을 수 있다.

이것은 앱 내부 데이터 이전이다. 폐기한 사본 파일 가져오기 화면을 다시 사용하는 과정이 아니다. 원본 Codex 로그는 DB 안에 복사되지 않는다.

두 PC가 하나의 OneDrive 동기화 DB를 동시에 열어 쓰는 구성은 검증하지 않았다. 각 PC의 로컬 디스크에 별도 앱·DB를 두고 중지한 상태의 백업으로 옮긴다. 기존 PC의 `.codex` 전체나 인증 파일을 설치 용도로 복사할 필요는 없다.

## 4. Node.js 확인과 첫 실행

Node.js 24.18 이상을 설치한 뒤 새 명령 프롬프트(CMD)를 열고 확인한다.

```bat
node --version
npm.cmd --version
```

예시 작업 폴더로 이동하고 설치·빌드·실행한다.

```bat
cd /d "C:\Tools\codex-flow-viewer"
npm.cmd ci
npm.cmd run build
start-viewer.cmd
```

CMD 경로에는 작은따옴표 대신 큰따옴표를 사용한다. `npm.cmd ci`는 인터넷이 필요하며 package-lock에 고정된 의존성을 설치한다. 각 명령이 성공했을 때 다음으로 진행한다.

이후에는 `start-viewer.cmd`를 더블클릭하면 된다. 이 스크립트도 의존성·빌드가 없으면 설치와 빌드를 시도하지만 처음에는 위 명령을 하나씩 실행하면 오류를 확인하기 쉽다.

브라우저 주소:

```text
http://127.0.0.1:4318
```

새 서버를 실행한 검은 창은 사용 중에 닫지 않는다. 창을 닫으면 서버도 종료될 수 있다. 이미 서버가 실행 중이라는 안내만 나온 창은 닫아도 기존 서버는 계속 실행된다. 현재 프로그램은 컴퓨터 시작 시 자동 실행하거나 종료된 서버를 자동 복구하지 않는다. 프로그램 업데이트 후에는 다시 빌드해야 최신 화면이 적용된다.

## 5. Codex 기록 연결 — 이 기능만 쓰면 MCP는 불필요

1. 새 PC에서 Codex로 실제 프로젝트를 열고 대화를 사용한다.
2. 뷰어의 설정 → Codex 프로젝트를 선택한다.
3. 프로젝트 폴더에는 **새 PC의 실제 작업 폴더**를 입력한다. 예: `C:\Projects\my-project`.
4. 기록 위치에는 보통 아래 경로를 입력한다. 사용자 이름을 새 PC 계정에 맞춘다. CODEX_HOME을 별도로 설정한 환경은 그 위치를 사용한다.

```text
C:\Users\새사용자\.codex\sessions
```

5. ‘기록에 있는 프로젝트’ 목록에서 정확한 경로를 선택할 수도 있다. ‘프로젝트 연결’을 눌러 적용한다.

폴더가 있어도 그 경로에 일치하는 Codex 기록이 없으면 대화는 나타나지 않는다. ChatGPT 채팅 제목을 프로젝트 폴더에 입력하지 않는다.

예전 PC의 기록을 별도로 옮겼어도 로그에 저장된 프로젝트 경로와 새 PC 경로가 달라지면 바로 연결되지 않을 수 있다. 현재는 임의의 옛 경로→새 경로 매핑 기능이 없다. 원본 로그의 경로를 수정해서 맞추지 않는다. 새 PC에서 새로 만든 기록부터 연결하는 방법이 가장 단순하다.

## 6. 데스크톱 채팅 → MCP → 뷰어 연결

### 6-1. 새 PC에 로컬 MCP 등록

현재 PC에서 확인한 데스크톱 메뉴는 설정 → 플러그인 → MCP다. 공식 문서는 데스크톱 앱·Codex CLI·IDE가 MCP 설정을 공유한다고 안내한다. 새 PC에서도 해당 로컬 실행 환경과 도구 노출을 실제로 확인한다. 앱 버전·계정·실행 모드의 호환성을 로그인만으로 보장하지 않는다.

CMD에서 Codex CLI가 인식된다면 다음을 실행한다. Node가 다른 위치에 설치됐다면 `where node`로 실행 파일 위치를 확인해 바꾼다.

```bat
codex mcp add flow-viewer -- "C:\Program Files\nodejs\node.exe" "C:\Tools\codex-flow-viewer\server\mcp\stdio.mjs"
codex mcp list
```

이미 flow-viewer가 등록됐다면 새 항목을 중복 추가하지 말고 기존 항목의 실행 경로가 새 PC 경로인지 확인한다. 프로그램 폴더를 나중에 이동하면 이 경로도 바꿔야 한다.

`codex` 명령이 인식되지 않는 경우에는, 로컬 MCP 설정을 지원하는 대상 앱의 사용자 설정 파일에 아래 **한 항목만** 추가·수정하는 대안이 있다. 기본 경로는 `%USERPROFILE%\.codex\config.toml`이다. CODEX_HOME을 별도로 사용하는 경우 해당 설정 위치를 확인한다. 기존 설정 전체를 교체하지 않는다.

```toml
[mcp_servers.flow-viewer]
command = 'C:\Program Files\nodejs\node.exe'
args = ['C:\Tools\codex-flow-viewer\server\mcp\stdio.mjs']
```

이 TOML 조각의 작은따옴표는 설정 파일 문법이며 앞의 CMD 경로 입력 문법과 다르다. 이 절은 로컬 MCP를 지원하는 앱 구성에 대한 것이다. 해당 메뉴·설정 지원이 없는 환경을 서버 URL 입력으로 대체할 수는 없다. 현재 수신기는 STDIO이며 `http://127.0.0.1:4318`은 뷰어 주소이지 MCP 서버 URL이 아니다.

### 6-2. 도구 노출 확인

데스크톱 앱을 다시 열고 설정 → 플러그인 → MCP에서 flow-viewer를 켠다. 이전 도구만 보이면 해당 서버를 껐다 켜고 필요하면 새 로컬 채팅에서 확인한다. 다음5개가 보여야 한다.

```text
flow_status
flow_list_projects
flow_create_project
flow_start_conversation
flow_record
```

채팅에 다음과 같이 요청한다.

```text
flow-viewer의 flow_status 도구를 호출해서 연결 상태를 확인해줘.
```

실제 호출 결과의 status=ready, recordingAvailable=true를 확인한다. 앱 목록에 서버 이름이 있다는 것과 실제 도구 호출 성공은 구분한다. MCP 서버는 데스크톱 호스트가 실행하므로 stdio.mjs를 별도 콘솔에서 수동으로 켜둘 필요는 없다.

### 6-3. 뷰어에서 프로젝트를 열고 실제 전송

1. 뷰어의 설정 → ChatGPT 대화에서 프로젝트를 만든다. DB를 옮겼다면 기존 프로젝트를 선택할 수 있다.
2. 프로젝트를 선택하고 ‘프로젝트 열기’를 누른다.
3. 설정에 표시되는 ‘ChatGPT에서 사용할 연결 문구’를 복사해 **MCP 도구가 보이는 로컬 채팅**에 붙여넣는다.
4. 실제 질문·답변 하나를 이 프로젝트에 전송하도록 요청한다. 도구가 반환한 저장 성공 영수증을 확인한다.
5. 뷰어 왼쪽의 해당 대화를 열어 질문·답변을 확인한다. 정상 실행 중에는 약2초 간격으로 갱신된다.

프로젝트 선택만으로 모든 ChatGPT 대화가 자동 전송되지 않는다. MCP는 실제 도구 호출로 보낸 내용만 저장한다. 일반 채팅의 모든 답변을 빠짐없이 자동 수집하는 기능은 보장하지 않는다.

기본 설정에서는 MCP와 화면 서버가 같은 앱 폴더의 `.local/viewer.sqlite`를 사용한다. VIEWER_DB를 따로 설정했다면 두 프로세스가 같은 절대경로를 사용해야 한다. 프로그램을 두 군데 복사하고 MCP는 A폴더, 화면은 B폴더에서 실행하면 서로 다른 기록을 볼 수 있다.

## 7. 매일 사용할 때

1. 새 PC에서 `start-viewer.cmd`를 실행하고 실행 창을 유지한다.
2. 브라우저에서 `http://127.0.0.1:4318`을 연다.
3. 왼쪽 출처와 프로젝트가 원하는 Codex/직접 연결 프로젝트인지 확인한다.
4. Codex는 해당 PC의 로컬 기록을 읽는다. MCP는 데스크톱 채팅에서 보낸 기록이 있어야 목록이 쌓인다.
5. 메모·고정은 그 PC의 DB에 저장된다. 다른 PC로 옮기려면 중지 후 백업 과정이 필요하다.

## 8. 문제가 있을 때

| 증상 | 확인할 것 |
|---|---|
| 주소가 열리지 않음 / 연결 거부 | 뷰어 서버 실행 여부. start-viewer.cmd를 다시 실행하고 오류 확인 |
| 실행 창이 바로 끝남 | Node 버전, 복사한 프로그램 파일, 설치·빌드 오류를 CMD에서 하나씩 확인 |
| node/npm을 찾을 수 없음 | Node 설치 후 CMD를 새로 열고 node --version 확인 |
| MCP는 정상인데 뷰어가 안 열림 | MCP 수신기와 HTTP 화면 서버는 별개. 뷰어도 실행 |
| ChatGPT 기록 대신 다른 프로젝트가 나옴 | 설정에서 ChatGPT 대화와 정확한 직접 연결 프로젝트를 열기 |
| 대화 목록이 비어 있음 | 새 DB인지, 프로젝트를 맞게 골랐는지, 실제 flow_record 저장 영수증이 있는지 |
| 저장 성공인데 안 보임 | MCP 실행 경로와 뷰어 실행 폴더, VIEWER_DB 일치 여부, 검색어/필터 확인 |
| flow_status만 보임 | 실행 경로가 최신 파일인지 확인하고 MCP 연결 갱신·앱 재시작 후 실제5도구 확인 |
| Codex 폴더는 있는데 대화0개 | 로그에 기록된 실제 프로젝트 경로와 현재 폴더가 일치하는지 |
| 이전 PC 기록·메모가 없음 | 소스만 복사했는지, 중지 후 .local 데이터도 옮겼는지 |
| 다른 PC에서 같은 주소를 열어도 예전 기록이 없음 | localhost는 각 PC 자신이며 자동 동기화 기능이 아님 |

## 9. 근거와 확인 범위

- 로컬 확인: start-viewer.cmd, scripts/launch.mjs, server/start.mjs, server/mcp/stdio.mjs, server/store.mjs, package.json 및 codex mcp add --help.
- MCP 등록·공유 설정: [OpenAI 공식 MCP 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
- 기존 PC의 실제 모델→MCP 저장→뷰어 표시와 운영 복구는 확인했다. 새 PC 설치·계정별 지원·다중 PC 병합·자동 실행은 이번 문서 작성에서 시험하거나 구현하지 않았다.
